# Mes projets

Tags : projet, projets, kanban, trello, jira, tableau kanban, gestion de projet, cartes, colonnes, backlog, sprint, développement, équipe, collaboration, story points, labels, sous-tâches, roadmap, bug, fonctionnalité, premium, entrepreneur

## Présentation

Le module **Mes projets** permet de gérer ses projets grâce à un tableau **Kanban**, inspiré d'outils comme **Trello** ou **Jira**.

Il permet de suivre l'avancement des développements, des projets personnels ou professionnels à travers des colonnes et des cartes.

Cette fonctionnalité est accessible depuis :

- **Entrepreneuriat → Mes projets**

L'URL visible est :

`/projects`

---

# Offre gratuite

L'offre gratuite permet de :

- créer un projet ;
- modifier un projet ;
- supprimer un projet ;
- créer des cartes ;
- modifier des cartes ;
- supprimer des cartes ;
- gérer un tableau Kanban ;
- inviter jusqu'à **2 membres** par projet.

---

# Offre Premium

L'abonnement **Premium** débloque :

- jusqu'à **10 projets** ;
- jusqu'à **10 membres par projet** ;
- toutes les fonctionnalités collaboratives avancées.

---

# Création d'un projet

Lors de la création d'un projet, l'utilisateur peut renseigner :

- le nom du projet ;
- une description ;
- une couleur ;
- une icône.

Chaque projet est ensuite affiché sous forme de carte.

Une carte affiche notamment :

- le nombre de cartes ;
- le nombre de colonnes ;
- le nombre de membres.

---

# Tableau Kanban

Chaque projet possède un tableau Kanban.

Les colonnes visibles peuvent par exemple être :

- Idée
- Prêt
- En cours
- À valider
- Terminé

Le fonctionnement est similaire à Trello ou Jira.

Les cartes sont déplacées d'une colonne à une autre selon leur état d'avancement.

---

# Colonnes

Les utilisateurs peuvent créer leurs propres colonnes.

Exemples :

- Backlog
- À faire
- En cours
- En attente
- À tester
- Validé
- Terminé

Les colonnes peuvent être renommées ou supprimées.

---

# Cartes

Chaque colonne peut contenir plusieurs cartes.

Une carte représente généralement :

- une fonctionnalité ;
- un bug ;
- une amélioration ;
- une tâche technique ;
- une idée.

---

# Informations d'une carte

Une carte peut contenir :

- un titre ;
- une description ;
- un type ;
- une priorité ;
- un responsable ;
- une date limite ;
- des labels ;
- des Story Points ;
- des sous-tâches.

---

# Priorités

Les priorités visibles comprennent notamment :

- Basse
- Moyenne
- Haute
- Urgente

---

# Types

Le type d'une carte peut être personnalisé.

Les captures montrent notamment des cartes de type :

- Bug
- Fonctionnalité

Scalia ne doit pas inventer d'autres types.

---

# Labels

Chaque carte peut recevoir plusieurs labels.

Les labels servent à catégoriser les cartes.

Plusieurs labels peuvent être renseignés.

---

# Story Points

Les cartes peuvent posséder des **Story Points**.

Ils permettent d'estimer la complexité ou l'effort d'une tâche.

---

# Sous-tâches

Chaque carte peut contenir plusieurs sous-tâches.

Les sous-tâches permettent de découper une fonctionnalité en plusieurs étapes.

Chaque sous-tâche peut être ajoutée directement depuis la carte.

---

# Gestion d'équipe

Chaque projet possède une équipe.

En version gratuite :

- maximum **2 membres**.

En Premium :

- jusqu'à **10 membres**.

Les membres peuvent être :

- propriétaire ;
- membre.

---

# Déplacement des cartes

Les cartes peuvent être déplacées entre les colonnes.

Le tableau permet ainsi de suivre l'avancement du projet.

---

# Cas d'utilisation

Le module peut être utilisé pour :

- gérer un projet logiciel ;
- organiser une roadmap produit ;
- suivre des bugs ;
- préparer un lancement marketing ;
- organiser un projet immobilier ;
- suivre une équipe ;
- gérer un projet entrepreneurial.

---

# Comparaison

Le fonctionnement est similaire à :

- Trello
- Jira
- GitHub Projects

Scalia peut utiliser ces comparaisons pour aider l'utilisateur à comprendre rapidement le fonctionnement.

---

# Limites documentaires

Les captures ne permettent pas de confirmer :

- les notifications ;
- les commentaires ;
- les pièces jointes ;
- l'historique des modifications ;
- l'automatisation des cartes ;
- les intégrations externes.

Scalia ne doit jamais inventer ces fonctionnalités.
